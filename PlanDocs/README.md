# 计划讨论交接

本目录是几个模型讨论**方向、顺序和验收口径**时的唯一交接区。代码改动的审核仍走 `CRDocs/`。设计基线仍是 `Docs/OLP_System_Design_Claude.md`（v1.1）。本目录不产生第二份基线。

双方开始前先读本文件、`STATUS.md`。提案方再读 `REVIEW.md`。审核方再读 `PROPOSAL.md`，并只扫 `DECISIONS.md` 里已采纳条目的标题和「未决假设」，避免把已经拍板的事重新打开。

## 角色

### 提案方

1. 把要决定的事写成 `PROPOSAL.md`，覆盖上一题留下的正文。
2. 用户指出一份已有意见（聊天记录或 `temps/` 里的稿）时，先收成下面的固定标题，不把原文当作提案。
3. 收到审核后，只改 `PROPOSAL.md`。每一条审核意见标明 `采纳`、`部分采纳` 或 `不采纳`，并写一句核对过的证据。不采纳必须指出文件、测试或计划条文，不能只重复原话。
4. 写完把 `STATUS.md` 改为 `READY_FOR_REVIEW`。
5. 不改 `REVIEW.md`，不改 `DECISIONS.md`。

### 审核方

1. 只根据 `PROPOSAL.md` 审核，不根据聊天印象。
2. 事实到仓库里核对：打开提案点名的源码、测试和计划。声称「仓库里没有」之前要先搜索，并写明搜索范围。
3. 默认不改业务代码，不改 `PROPOSAL.md`。
4. 结论写入 `REVIEW.md`，使用下面的固定标题。
5. 同意也要写核对了哪个文件。不能只写「同意」。
6. 只有下一件会因此做错时，才要求改顺序。可以留到后一步的前提，不要提前塞进当前这一步。
7. 不建议新写 `Docs/` 基线，不建议为讨论本身新增类或子系统。

## 状态

```text
IDLE
  → PROPOSING
  → READY_FOR_REVIEW
  → CHANGES_REQUESTED → PROPOSING（下一轮）
  → CONVERGED
  → ADOPTED
  → IDLE
```

`BLOCKED`：缺用户决定或外部条件，讨论无法安全继续。

一轮审核之后：

- 存在会改变下一件工作的事实错误、顺序问题或遗漏：`CHANGES_REQUESTED`。
- 没有这类问题：`CONVERGED`。措辞、命名和「也可以做」不挡住收敛。

最多 3 轮。第 3 轮审核必须写成 `CONVERGED` 或 `BLOCKED`，不能再要求下一轮。还没一致的点写入决定的「未决假设」。

## 文件所有权

| 文件 | 谁写 | 用途 |
|---|---|---|
| `README.md` | 用户或经用户授权的一方 | 固定规则 |
| `STATUS.md` | 当前交棒方 | 话题、轮次、状态 |
| `PROPOSAL.md` | 提案方 | 这一题的提案 |
| `REVIEW.md` | 审核方 | 这一轮的独立审核 |
| `DECISIONS.md` | 用户确认采纳的那一方 | 已采纳决定的短记录 |

## 提案固定标题

```text
## 要决定的问题
## 建议决定
## 证据
## 未核实
## 建议顺序
## 明确不做
## 对上一轮审核的处理
```

第一轮没有审核时，「对上一轮审核的处理」写「无」。证据写路径和行为，不写印象。

## 审核固定标题

```text
## 本轮核对了什么
## 属实
## 不成立或说重了
## 遗漏
## 顺序
## 未核实
## 结论
```

「顺序」只能是「不改」或一份改过的顺序。结论只能是 `CHANGES_REQUESTED`、`CONVERGED` 或 `BLOCKED`。

## 采纳

用户明确说讨论可以收口之后，被点名的那一方才把短决定追加到 `DECISIONS.md`，并刷新 `.claude/Plan.md` 与 `.claude/SessionBrief.md`。决定只留：日期、话题编号、决定、顺序、未决假设、计划写在哪。然后把 `STATUS.md` 设回 `IDLE`，`PROPOSAL.md` 和 `REVIEW.md` 改成「上一题已归档」。

`ADOPTED` 只表示方向已经拍板。对应的代码任务另行打开 `CRDocs/`，不在本目录里审 diff。

## 用户最简操作

对提案方：

> 读取 PlanDocs，把这件事写成提案并交接。

对审核方：

> 读取 PlanDocs，独立审核这一轮提案。

提案被审核之后，对提案方：

> 读取 PlanDocs，按 REVIEW.md 修正提案并交接。

用户确认可以收口时：

> 读取 PlanDocs，讨论已收敛，写入决定并更新计划。
